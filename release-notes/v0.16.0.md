Heavy jobs can now run on the Vost server: backtests, optimizer runs, Monte Carlo runs and the strategy maker's Find, Retrain and market search go to a pool of worker threads on the server when you pick **Server** (or **Auto**, after a benchmark) in Settings, and they keep going when the tab closes. The strategy maker gains a market search across ranked crypto, stock and index lists, and labels the style of your marked trades. The backtester gains risk-per-trade sizing, ATR stops, targets in R and trailing stops (with the ATR optionally on a longer timeframe), a Composed strategy of one entry rule plus filters, three new built-in strategies and entry signal counts. The server now needs its engine bundle, which `npm run build` makes (see the upgrade notes).

## Highlights

- **Heavy jobs on the server**: in Settings, [**Heavy jobs**](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/backtesting.md#where-heavy-jobs-run) can send backtests, optimizer runs and Monte Carlo runs of built-in strategies to the Vost server instead of this tab. A server run shows the same progress and results, keeps going when you close the tab or reload, and its result shows when you reopen the chart; a run that finished while Vost was closed adds a note to the inbox. Pine and custom-code strategies and chart indicators always run in the browser. If the server cannot take a job, it runs in the browser and a message says why.
- **Find, Retrain and market search on the server**: the same choice sends the strategy maker's [Find, Retrain and **Search markets**](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/strategy-maker.md#where-find-and-the-market-search-run) to the server; reopening the page picks the run up again with its progress or shows its result.
- **Benchmark and Auto**: [**Run benchmark**](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/backtesting.md#the-benchmark-and-auto) times five standard jobs in the browser and on the server and shows both side by side; **Auto** then runs each kind of job where it was faster, and in the browser until a benchmark exists.
- **Search many markets**: the strategy maker's [**Search markets**](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/strategy-maker.md#searching-many-markets) tries many indicator settings and exits across market lists (live top 30 crypto by market cap and by volume, fixed stock and index lists) and timeframes, sized by risk per trade, and keeps the ones that meet your targets and hold on a held-out 30%. It can try Composed strategies, ATR stops and ATR trailing stops, ask results to beat buy and hold on unseen data, and run a chance baseline on shuffled copies of the same markets. **Open in Backtest** opens the result's market and timeframe with every setting filled in.
- **The style of your trades**: Find [labels each marked trade](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/strategy-maker.md#the-style-of-your-trades) as trend following, trend continuation, mean reversion, reversal, breakout, momentum or no clear style, shows the mix with a reason per trade, and searches the families of the leading style.
- **Risk per trade**: [**Position sizing**](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/backtesting.md#risk-per-trade) can size each trade so that its stop loses a set percent of equity, with no cap on the position; the **Max leverage** card shows the largest leverage used. It needs a stop.
- **ATR stops, R targets and trailing stops**: [stop loss, take profit and trailing stop](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/backtesting.md#stops-take-profits-and-trailing-stops) each have a mode: percent, ATR multiple, or (for the take profit) times the stop. The ATR can be measured on a longer timeframe built from the loaded bars. Find in the strategy maker tries these exits too, and Open in Backtest and Copy as Pine strategy carry them.
- **Composed strategy**: [**Composed**](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/backtesting.md#composed-strategy) takes entries from one rule (SMA or EMA crossover, MACD, RSI, Bollinger or Donchian) and lets trend, volume, volatility and ADX filters veto them, with the trend and volatility filters optionally on a longer timeframe, and counts the entries each filter blocked.
- **New strategies**: [Pullback in trend, Reversal and Momentum breakout](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/backtesting.md#the-backtest-pane) join the built-in strategies.
- **Entry signals**: the Results tab's [**Entry signals** and **Signal rate**](https://github.com/cbundy/Vost/blob/v0.16.0/docs/guide/backtesting.md#results) cards say how many signals fired, how many were taken, and the rate per 100 bars and per day; the optimizer CSV, the strategy maker's ranked settings and the market search show them too.
- **Under the hood**: a Node engine bundle (`server/dist/engine.mjs`) and a worker-thread job pool run the server jobs behind a new `/api/jobs` API (start, follow, cancel, read); `/api/market-lists` builds the crypto lists from CoinGecko or CoinMarketCap; CI smoke-tests the engine bundle and the jobs API in Node and in the Docker image; new capture scenarios cover server jobs, the benchmark, the market search and the new exits.

## Upgrade notes

- **Rebuild: the server now needs its engine bundle.** `npm run build` now also builds `server/dist/engine.mjs`, which the server runs in worker threads for `/api/jobs`. From source, update as usual (`git checkout v0.16.0 && npm ci && npm run build`, then restart); `npm run dev:server` builds it first too. Without the bundle the server still starts and everything else works, the start log says `engine bundle missing`, `/api/jobs` answers `503 { error: "server jobs unavailable: run npm run build" }`, and the app runs every heavy job in the browser with a message saying so.
- **Docker: rebuild the image.** The `Dockerfile` now copies `server/dist` from the build stage into the image (and `.dockerignore` leaves out a local `server/dist`), so `docker compose up -d --build` at the tag is all that is needed. `docker-compose.yml` is unchanged.
- **Heavy jobs stay in the browser until you choose otherwise.** The new Settings choice **Heavy jobs** (**Browser**, **Server** or **Auto**) defaults to **Browser**, so nothing is sent to the server after the upgrade until you pick another place. It is saved as `jobPlace` in the `prefs.v1` setting (missing or bad reads as browser), and a benchmark result as the `benchmark.v1` setting.
- **Server jobs use the server's CPU.** At most `VOST_JOB_WORKERS` jobs run at once (new variable, default: the CPU count minus one, at least 1; anything but a positive integer uses the default); the rest wait queued, in order. On a small or shared host, set it to `1` (or so) to keep the server responsive; an optimizer run or market search on the server can keep a worker busy for minutes.
- **New `jobs/` folder in the data folder.** `VOST_DATA_DIR` now also holds `jobs/` (one file per server job: its summary and, once done, its result; the newest 100 finished jobs are kept) and `strategy-maker/job.json` (the run the strategy maker page is waiting for). Both are created on first write and live on the same `/data` volume as before; no volume change is needed. If the folder is not writable, `/api/jobs` answers `503` and jobs run in the browser. A job still running when the server stops is marked `interrupted` at the next start, and the app says the run is gone.
- **New optional variable `VOST_COINMARKETCAP_API_KEY`.** The crypto lists of the market search (`GET /api/market-lists`) come from CoinGecko, with no key. With a free CoinMarketCap key set, CoinMarketCap is asked first and CoinGecko second. The key is a secret, never logged or returned. An outbound firewall must allow `api.coingecko.com` (and `pro-api.coinmarketcap.com` with a key); each list is cached for 24 hours.
- **New API endpoints**: `/api/jobs` (`POST`, `GET`, `GET /api/jobs/<id>`, `DELETE /api/jobs/<id>`, `GET /api/jobs/events` event stream; same-origin only like `/api/settings`, bodies up to 64 MB, so the `client_max_body_size 128m;` advised for v0.15.0 covers it), `/api/strategy-maker/job`, and `GET /api/market-lists`; see `docs/DEPLOYMENT.md`. `/api/jobs/events` is a server-sent-events stream that replies with `X-Accel-Buffering: no` and a `: ping` heartbeat, like `/api/live`; a proxy that ignores that header needs buffering off for it as for `/api/live` (see `docs/DEPLOYMENT.md`). No existing endpoint changed.
- **Downgrading to v0.15.x**: v0.15.x does not use the `jobs/` folder, `strategy-maker/job.json` or the `benchmark.v1` setting; they are left in place and come back into use when you upgrade again. A run still going on the server is lost.

To deploy, build from the tag (`git checkout v0.16.0`, then `docker compose up -d --build`); no registry image of the app is published. Nothing in your `.env` needs to change; optionally set `VOST_JOB_WORKERS` and `VOST_COINMARKETCAP_API_KEY`.
