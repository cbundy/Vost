A Pine script that asks for data Vost does not have (company financials, economic data, Pine Seeds, dividends, splits or earnings) now stops with a message naming the call, instead of running on and showing an empty plot. Errors from `request.security_lower_tf` now name that call.

## Highlights

- **Fix: Pine data calls Vost lacks stop the run**: `request.financial`, `request.economic`, `request.seed`, `request.dividends`, `request.splits` and `request.earnings` [stop the script with a plain message](https://github.com/cbundy/Vost/blob/v0.13.1/docs/guide/pine.md#what-a-script-sees-of-the-chart), such as `request.earnings() is not available in Vost: it has no earnings data`, wherever the call sits. Before, the script ran and showed an empty plot with only a warning. `request.footprint` and `request.quandl` are unchanged.
- **Fix: `request.security_lower_tf` errors name the call**: when the lower-timeframe bars cannot load (the 20000-bar cap, a failed fetch, a symbol not found), the [message](https://github.com/cbundy/Vost/blob/v0.13.1/docs/guide/pine.md#what-a-script-sees-of-the-chart) now starts with `request.security_lower_tf(` instead of `request.security(`.
- **Under the hood**: `request.security_lower_tf` on the chart's own symbol is now pinned by tests (closes in time order per chart bar, nothing past the run end, an imported dataset refusing a lower timeframe), the engine pin check covers the six unavailable calls, and the Pine coverage map and probe output are updated.

## Upgrade notes

- **Scripts that call these six functions now stop**: a script that calls `request.financial`, `economic`, `seed`, `dividends`, `splits` or `earnings` used to run with an empty value; it now fails with a message in the Pine pane, and a backtest or optimizer run of such a strategy fails the same way. Remove the call to run the script.
- **No other change.** Saved browser data, the API, the server and deploy config are unchanged from 0.13.0, and no dependency changed (PineTS stays 0.13.0).

To deploy, build from the tag (`git checkout v0.13.1`, then `docker compose up -d --build`); no registry image of the app is published. Nothing in your environment or `.env` needs to change.
