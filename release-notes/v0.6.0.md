Vost gets a new look, price alerts that keep watching with every tab closed (with optional Telegram messages), bar replay, five drawing tools and live quotes in the watchlist.

## Highlights

- **Redesign**: a near-black theme with a slimmer 40px icon-led top bar; a one-line coloured chart legend and a bar under the chart with quick ranges (1D to All), the Range picker and the time-zone clock; the side panel moves to the right with an icon rail (a right-edge drawer on narrow screens); and the Pine editor opens in its own resizable pane beside the chart from a new Pine Editor button in the top bar (a dialog on windows 900px wide and below). The bottom panel keeps Backtest, Optimizer and Results.
- **Price alerts**: the server now stores alerts and watches prices for them around the clock, so an alert fires once when the price crosses its level even with every browser tab closed. Manage them from the new Alerts panel, the bell in the top bar or the chart's right-click menu; a popup shows each alert as it fires.
- **Telegram on fire**: set `VOST_TELEGRAM_BOT_TOKEN` and `VOST_TELEGRAM_CHAT_ID` and every alert that fires also sends one Telegram message. A test button checks the setup.
- **Bar replay**: pick a starting bar (click it or type a date), then step or play forward at 1, 3 or 10 bars a second. The chart, indicators, Pine output and trade markers see no look-ahead; backtests still use all the data and live bars keep arriving in the background.
- **Drawing tools**: a rail beside the chart with trend line, horizontal line, ray, rectangle and Fibonacci retracement. Select, move, resize, delete, undo and redo; drawings are saved per symbol and keep their place across zoom, timeframe changes and live bars.
- **Watchlist quotes**: watchlist rows show last price, change and change percent from their own data source, and a symbol card shows more detail for the selected row.

## Upgrade notes

Saved browser data and the existing API are unchanged: old preferences load with defaults for the new settings, and drawings use a new storage key.

**Deploy config changes** (new in this release):

- The server now writes one file, `alerts.json`, in `VOST_DATA_DIR` (default `<repo>/data`, `/data` in the Docker image). A read-only filesystem is no longer enough if you want alerts: the folder must be writable, or the server still starts but every alert change answers `503`.
- Docker: the image declares a `/data` volume and `docker-compose.yml` now mounts a named volume `vost-data` there. With plain `docker run`, add `-v vost-data:/data` to keep alerts across container re-creation.
- New optional environment variables (see `docs/DEPLOYMENT.md` and `.env.example`):
  - `VOST_DATA_DIR`: folder for `alerts.json`.
  - `VOST_ALERT_POLL` (default `60`, minimum `10`): seconds between price polls for alerts on providers without a live feed (Coinbase, Yahoo, Stooq).
  - `VOST_TELEGRAM_BOT_TOKEN` and `VOST_TELEGRAM_CHAT_ID`: both must be set to send Telegram messages; with only one set the server logs a warning and sends nothing. The token is a secret: keep it out of git and tickets. Sending needs outbound access to `api.telegram.org`. `docker-compose.yml` passes both through from the host environment.
- New API: `/api/alerts` (list, create, update, delete), `/api/alerts/events` (event stream) and `POST /api/alerts/telegram-test`. Alert changes are same-origin only, so a reverse proxy must pass the `Host` header through unchanged.

To deploy, build from the tag (`git checkout v0.6.0`, then `docker compose up -d --build`); no registry image of the app is published.
