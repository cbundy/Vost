Hyperliquid joins the providers, the server now records BTC and ETH at all times, charts can use any interval built from a lower timeframe (live included), Pine scripts can import TradingView libraries, and a new /compare page diffs Pine scripts. Stooq is gone as a data source.

## Breaking

- **Stooq is no longer a data source.** Its CSV download now sits behind a browser challenge a server cannot answer, so it had stopped returning data. Yahoo Finance and CSV import cover the same assets, and CSV import still reads Stooq's own CSV export format. What happens to saved data that names Stooq:
  - **Charts**: a chart last left on Stooq opens on the default market (Binance BTCUSDT 1h) instead.
  - **Watchlists**: Stooq entries are removed from your saved watchlists the first time the new version opens, and the cleaned lists are saved. A section left empty only by that is removed (a list keeps at least one section). They do not come back after a downgrade, so note the symbols first if you want to re-add them from Yahoo (for example `aapl.us` on Stooq is `AAPL` on Yahoo).
  - **Alerts**: Stooq alerts stay in `alerts.json` and stay listed as active, but they are never checked and never fire. The server logs `[alerts] stooq <SYMBOL> stooq is no longer offered` once per alert at start. Delete them in the Alerts panel and recreate them on Yahoo.
  - **API**: `/api/history`, `/api/symbols` and `/api/search` with `provider=stooq` answer `400 Unknown provider "stooq"`, `/api/live` refuses it, and `/api/providers` no longer lists it.
  - **Config**: no variable is dead. `VOST_ALERT_POLL` still applies, now only to Yahoo alerts (every other provider's alerts use the live stream). A `stooq:` entry in `VOST_RECORD` is skipped with a `[recorder]` warning. An outbound firewall rule for `stooq.com` can be removed.

## Highlights

- **Hyperliquid Perps and Hyperliquid Spot**: two new providers with chart history, symbol search, live candles and alerts, all fetched by the server. Symbols resolve in any letter case (`kpepe` is `kPEPE`, `hype/usdc` is spot `@107`). Hyperliquid serves at most its latest 5000 bars per timeframe.
- **Recorded markets (`VOST_RECORD`)**: the server now keeps a list of markets recorded at all times into the candle store added in v0.8.0. By default that is BTC and ETH on Binance, Coinbase and Hyperliquid Perps, on every timeframe, kept back to 20000 bars. Charts of a recorded market load from disk and ask the exchange only for what is missing. See the upgrade notes: this is on by default.
- **Any interval**: the server accepts any number-and-unit timeframe (`2h`, `10m`, `3d`, `2w`, `3M`) on `/api/history` and `/api/live` and builds it from the provider's best lower native timeframe. A non-canonical spelling (`120m`) answers 400 naming the canonical one (`2h`).
- **Built timeframes in the picker**: timeframes a provider lacks are built from a lower one and offered, marked `*`: Coinbase 30m, 4h, 1w and 1M, Kraken 1M and Yahoo 4h.
- **Build setting**: a Build toggle next to the timeframe picker (in the More menu on narrower screens), off by default, builds every timeframe above the provider's lowest from the next lower native one, for history and live. Built stock daily bars can differ slightly from the exchange's official ones, and OKX's own daily bars use UTC+8 days while built ones use UTC.
- **Live on built timeframes**: Live now works on built timeframes; the server folds the lower timeframe's live feed into the higher bar and shares the exchange socket with any chart open on that lower timeframe.
- **Yahoo full history**: Yahoo 1d, 1w and 1M charts asked for all history used to come back as quarterly or monthly bars. The server now asks by date window, and refuses a reply whose bar size differs from the one asked for instead of drawing it.
- **Pine libraries**: a Pine script that does `import user/name/version as x` now runs. The server looks the library up on TradingView (open-source libraries only) and keeps a copy. A library that cannot be fetched fails the run with a message naming it, and the new Libraries button in the Pine pane lets you paste its source once.
- **Pine compare page**: `/compare` puts 2 to 4 Pine scripts side by side and marks what was added, changed or removed against a chosen reference. The Pine editor head has a Compare link. The page loads no market data and runs no Pine code.
- **One live stream per tab**: all live charts in a tab now share one connection to the server, so a grid of up to 16 live charts no longer runs into the browser's six-connection limit.
- **Under the hood**: the client state is split into an app store and a per-chart store (groundwork for several charts), and `docs/spikes/pine-coverage/` maps which Pine v6 features Vost runs and shows, with a probe that can be re-run.

## Upgrade notes

- **Recording is on by default.** Leaving `VOST_RECORD` unset or empty (as `docker-compose.yml` passes it) records the default list: `binance:BTCUSDT binance:ETHUSDT coinbase:BTC-USD coinbase:ETH-USD hyperliquid-perps:BTC hyperliquid-perps:ETH`, every timeframe each provider streams live. Set `VOST_RECORD=off` to record nothing, or give your own list: entries separated by commas or spaces, each `provider:SYMBOL` or `provider:SYMBOL:tf/tf` (for example `binance:BTCUSDT:1h/1d`). `VOST_RECORD_BARS` (default 20000, minimum 100) sets the depth kept per series. Both are read once at start. A bad entry is skipped with a `[recorder]` warning.
  - **Network**: the server holds one live connection per recorded series for as long as it runs, about 45 with the default list. The first start fills every series back to the depth, one request at a time per exchange (Binance and Coinbase 250 ms apart, Hyperliquid 1 s): a few thousand requests over up to about ten minutes. Charts keep working meanwhile. Later restarts fetch only the bars missed since. On HTTP 429 or 418 an exchange's fill backs off from 60 s up to 15 minutes.
  - **Disk**: `candles.sqlite` in `VOST_DATA_DIR` grows to the order of 50 MB with the default list (about 90 bytes a row). A shorter `VOST_RECORD_BARS` shrinks it in proportion. A market taken off the list keeps its rows until you stop the server and delete `candles.sqlite` with its `-wal` and `-shm` siblings, which is safe: it is a cache and is rebuilt.
  - **Watching it**: the start log prints `[recorder] on: N series (...)`, each fill logs one `[recorder] ... filled` line, and `GET /api/status` gains a `recorder` section with per-series state, newest bar, missing bars and last error.
- **Outbound hosts.** An outbound firewall must now also allow:
  - `api.hyperliquid.xyz` on port 443, for HTTPS (`https://api.hyperliquid.xyz/info`) and the websocket (`wss://api.hyperliquid.xyz/ws`). With the default `VOST_RECORD` the server uses it from start, whether or not anyone opens a Hyperliquid chart.
  - `www.tradingview.com` and `pine-facade.tradingview.com` (port 443), only when a Pine script imports a library the server has not stored yet. These are TradingView's unofficial web endpoints and may change; pasting the library is the fallback.
  - The recorder's default list also keeps the Binance (`stream.binance.com:9443`, fallback `data-stream.binance.vision`) and Coinbase (`ws-feed.exchange.coinbase.com`) websockets open at all times, where before they opened only for a live chart or an alert.
- **Pine libraries at runtime.** The browser never calls TradingView; it asks the Vost server, which fetches a library the first time it is imported and saves it in a new file, `pine-libraries.json`, in `VOST_DATA_DIR`. A stored copy never expires, so scripts keep running when TradingView is down. A not-found or closed-source answer is remembered for 10 minutes; a network failure is not remembered. A pasted library is stored the same way. Back up `pine-libraries.json` along with `alerts.json` if you paste libraries. If the data folder is read-only, libraries are still fetched and served but not kept, and pasting answers 503.
- **`/api/live?sub=`.** The client now opens one `GET /api/live?sub=<key>&sub=<key>...` stream per tab (up to 16 keys; a key is `provider:timeframe:source:symbol`, and every event carries its `sub`). The old `?provider=&symbol=&timeframe=` form is still served unchanged, with untagged events. No reverse-proxy change is needed: the `location /api/live` block in `docs/DEPLOYMENT.md` (`proxy_buffering off`, a long `proxy_read_timeout`) matches the new form too. When the set of live charts changes the client opens the new stream before it closes the old one, so expect two `/api/live` connections from a tab for a moment.
- **`/compare`** is a client route. Behind the Node server or the documented proxy it works as is. On static-only hosting the host must fall back to `index.html` for `/compare`.
- **API additions**: `/api/history` and `/api/live` take an optional `source` (`native` or `built`; anything else is a 400) and any canonical interval; `/api/providers` lists `hyperliquid-perps` and `hyperliquid-spot`; `/api/status` gains `recorder` and has 23 checks (Hyperliquid added, Stooq removed, every provider now has a symbol-lookup check); new `GET /api/pine/libraries` and `GET`/`PUT`/`DELETE /api/pine/libraries/<user>/<name>/<version>` (writes are same-origin only, like the alert writes). Removed: `provider=stooq`.
- **Saved browser data**: no migration. The store split (#176) keeps `vost.prefs.v1` in its exact flat shape and keys, so the active chart, layout and settings restore as before, and a downgrade still reads them. New keys: `buildTimeframes` in `vost.prefs.v1` (the Build setting, off when absent) and `vost.compare.v1` (the compare page's panes). The one change to saved data is the removal of Stooq watchlist entries described under Breaking.

To deploy, build from the tag (`git checkout v0.9.0`, then `docker compose up -d --build`); no registry image of the app is published. Set `VOST_RECORD=off` in your environment or `.env` first if you do not want the recorder.
