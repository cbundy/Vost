The strategy maker's market search can now try a stored TradingView indicator's line plot as the stop of every Composed setting, fixed at entry or trailing the plot, with each take profit multiple read in R. Nothing about deploying or running Vost changes in this release.

## Highlights

- **A TradingView indicator as the stop in the market search**: the strategy maker's [**Search markets**](https://github.com/cbundy/Vost/blob/v0.18.0/docs/guide/strategy-maker.md#searching-many-markets) gains a **TradingView indicator stop** exit kind. Pick a stored indicator, one of its line plots, whether the stop is fixed at the entry bar or trails the plot, and its input values; it is tried on Composed settings only, adds one exit per take profit multiple (in R), and counts in the script runs. Result rows name it, for example `Supertrend Supertrend trailing / 3R`, and **Open in Backtest** carries the indicator stop card over with the R target.
- **Under the hood**: the sweep has a new exit kind `pine` (`ExitGrid.pineStop`), counted per setting kind by `sweepCombos` and once per script run by `pineRunCount`; new capture scenarios cover the indicator stop section, its count and its results.

## Upgrade notes

No upgrade steps are needed. The only change since v0.17.0 is in the browser app (the strategy maker's market search) and its docs and tests:

- **No deploy change.** The `Dockerfile`, `docker-compose.yml` and `.env` variables are unchanged, and no environment variable is added or removed.
- **No data or volume change.** No new file in the data folder; the `/data` volume is unchanged.
- **No proxy or API change.** No endpoint or event stream was added or changed.
- **Outbound network: no change.** The search runs stored indicators in the browser and contacts no new host.

Update as usual from source (`git checkout v0.18.0 && npm ci && npm run build`, then restart), or with Docker (`git checkout v0.18.0`, then `docker compose up -d --build`); no registry image of the app is published.
