The user guide is now built into Vost: a **Help** button in the top bar opens it at `/docs` on your own server, with every screenshot and no internet connection needed. Switching symbol also keeps the exact view you had, including empty space past the last bar. Docker users rebuild as usual; the image now ships the manual.

## Highlights

- **A built-in manual at /docs**: the new [**Help** button](https://github.com/cbundy/Vost/blob/v0.19.0/docs/guide/getting-started.md#the-manual) (a question mark left of the Settings gear; in the **More** menu on a phone-width screen) opens the user guide and the reference docs it links in a new tab, served by your Vost server at `/docs`. It works offline, in Docker and with `npm start`, always matches the running version (shown in its header), lists every page in a side list, and has **Back to Vost** to return to the chart. Links to files outside the manual open on GitHub at your version's tag.
- **The chart view carries across a symbol switch**: [switching symbol](https://github.com/cbundy/Vost/blob/v0.19.0/docs/guide/charts.md#switching-symbol) on the same timeframe now carries the view by bar positions, so the dates and zoom stay put and any empty space you had scrolled past the last bar is kept instead of being clipped to the new symbol's bars.
- **Under the hood**: `npm run build` gains a `build:docs` step (`scripts/docs/build.ts`, using the new `marked` dev dependency) that writes the manual to `client/dist/docs/` and fails on a missing image or link target; the guide heading-id helper moved to `scripts/guide-anchors.ts`. The drawing-image capture test builds its PNG with `node:zlib` `crc32`, and `CONTRIBUTING.md` documents the rule for crypto and checksum helpers.

## Upgrade notes

No configuration change is needed, but the build and the Docker image change:

- **Docker: the image now ships the manual.** The `Dockerfile` copies `docs/` and `scripts/` into the build stage, and `.dockerignore` now lets `docs/guide`, `docs/evidence` and `docs/*.md` through, so the built image serves `/docs`. Rebuild the image as usual (`git checkout v0.19.0`, then `docker compose up -d --build`); `docker-compose.yml` is unchanged. A custom build context that strips `docs/` or `scripts/` makes the build fail.
- **From source: run `npm ci` before building.** `npm run build` now also runs `npm run build:docs`, which needs the new `marked` dev dependency: `git checkout v0.19.0 && npm ci && npm run build`, then restart.
- **Proxy: `/docs` is a new path at the domain root.** The manual is served by the same server as the app, at `/docs` from the domain root (like `/api`). A reverse proxy that forwards everything (as in `docs/DEPLOYMENT.md`) needs no change; one that forwards only selected paths must also forward `/docs`. For local development the Vite dev server now proxies `/docs` to the API server (`VOST_SERVER_URL`, as before).
- **No environment variable change.** No variable is added or removed.
- **No data or volume change.** No new file in the data folder; the `/data` volume is unchanged.
- **Outbound network: no change.** The manual is served locally with its screenshots; only links to files outside the manual point at GitHub, and only when clicked.

No registry image of the app is published.
