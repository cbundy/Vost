Pine and custom-code strategies now follow the **Heavy jobs** setting and run on the Vost server like the built-in strategies when you pick **Server** (or **Auto** picks it). The Pine pane gains a library of open-source TradingView indicators, kept on the server with their author and licence, and the Composed strategy can use any stored indicator as its entry rule, a filter, its stop or its take profit, in the backtester, the optimizer and the strategy maker's market search. Read the upgrade notes before you turn on Server for a Vost other people can reach: user code on the server runs with the server's full rights.

## Highlights

- **Pine and custom code on the server**: with Settings, [**Heavy jobs**](https://github.com/cbundy/Vost/blob/v0.17.0/docs/guide/backtesting.md#where-heavy-jobs-run) on **Server** (or **Auto**, when it picks the server), backtests, optimizer runs and Monte Carlo runs of Pine and custom-code strategies go to the server too, keep going when the tab closes, and show the same progress and results. Only chart indicators always run in the browser.
- **TradingView indicators library**: [**TradingView indicators**](https://github.com/cbundy/Vost/blob/v0.17.0/docs/guide/pine.md#tradingview-indicators) in the Pine pane head searches TradingView by name or takes a `https://www.tradingview.com/script/...` link, and the server keeps a copy of the open-source indicator with its author and licence (your browser never contacts TradingView). **Open in editor** puts it on the chart; closed-source scripts, strategies and libraries are refused with the reason.
- **An indicator as the entry rule or a filter**: [**Composed**](https://github.com/cbundy/Vost/blob/v0.17.0/docs/guide/backtesting.md#composed-strategy) can take its entries from a stored TradingView indicator (a plot crossing another plot, the close or a level) or let one veto entries as a filter, with the script's own inputs under each one. Results count the entries each indicator filter blocked.
- **An indicator as the stop or the target**: the same [**Composed**](https://github.com/cbundy/Vost/blob/v0.17.0/docs/guide/backtesting.md#stops-take-profits-and-trailing-stops) strategy can place its stop (fixed at entry or trailing with the plot) or its take profit on an indicator's line plot, for example a Supertrend line. The indicator stop also sizes risk per trade and a take profit in times the stop, and the badges read `SL`, `Trail` or `TP` with the indicator and plot.
- **TradingView indicators in the market search**: the strategy maker's [**Search markets**](https://github.com/cbundy/Vost/blob/v0.17.0/docs/guide/strategy-maker.md#searching-many-markets) can try up to four stored indicators as extra Composed entry rules and four as filters, with a range searched over any number input. The page counts the script runs (limit 2,000), results name the indicator, rule and inputs, and **Open in Backtest** carries them over.
- **Under the hood**: `/api/jobs` now accepts Pine and custom-code strategies (it answered `422` before); a new `/api/pine/indicators` API searches, adds, lists and removes TradingView indicators kept in `pine-indicators.json`; a research spike (`docs/spikes/strategy-style-search/`) found no strategy of the strategy maker that beats buy and hold on unseen data more often than on shuffled copies of the same markets, from 1m to 4h; new capture scenarios cover the indicators library and the indicator roles.

## Upgrade notes

- **User code can now run on the server, with no sandbox.** With Heavy jobs on **Server**, or on **Auto** when it picks the server, the Pine and custom-code strategies a visitor writes run in the server's worker threads with the full rights of the Vost server process: they can read and write the data folder, read the environment (including `VOST_TELEGRAM_BOT_TOKEN` and `VOST_COINMARKETCAP_API_KEY`), open network connections and start child processes. Vost has no login, so anyone who can reach the page can run code on the host. Keep Vost on a trusted network, or put both `/` and `/api/*` behind a login at your reverse proxy (see `docs/DEPLOYMENT.md`, "Running user code on the server"). The Docker image runs the server as the unprivileged `node` user, which limits the damage to the container and its `/data` volume; a bare `npm` install runs it as whatever user starts it, so do not run that as root. There is no setting to keep Pine and custom code in the browser while sending other jobs to the server.
- **Check your Heavy jobs choice if you set it in v0.16.0.** The default is still **Browser**, so nothing changes until you pick another place. But if you already chose **Server** or **Auto**, Pine and custom-code strategies follow that choice from this release on, where they always ran in the browser before. Switch back to **Browser** if the trust rule above does not fit your setup.
- **New file in the data folder: `pine-indicators.json`.** It holds the TradingView indicators you add, with their source, author and licence, and lives beside `pine-libraries.json` on the same `/data` volume; it is created on first write, and an unreadable file is renamed `pine-indicators.json.bad-<time>`. No volume change is needed; back it up with the rest of the data folder.
- **Outbound network: no new hosts.** The indicators library uses the same two TradingView hosts as the Pine libraries, `www.tradingview.com` and `pine-facade.tradingview.com`, so a firewall that already allows them needs nothing new. TradingView's endpoints are unofficial and may change.
- **New API endpoints**: `GET /api/pine/indicators/search?q=`, `GET` and `POST /api/pine/indicators`, and `GET` and `DELETE /api/pine/indicators/<scriptId>`; writes are same-origin only like the library writes. No new event stream, so no proxy buffering change. `POST /api/jobs` no longer refuses `pine` and `custom` strategies with `422`; no other endpoint changed.
- **No deploy change.** The `Dockerfile`, `docker-compose.yml` and `.env` variables are unchanged, and no new environment variable is added. Update as usual from source (`git checkout v0.17.0 && npm ci && npm run build`, then restart), or with Docker (`git checkout v0.17.0`, then `docker compose up -d --build`).
- **Downgrading to v0.16.x**: v0.16.x does not use `pine-indicators.json`; it is left in place and comes back into use when you upgrade again. TradingView indicator roles in a Composed strategy are a v0.17.0 feature, so do not expect v0.16.x to run them.

To deploy, build from the tag (`git checkout v0.17.0`, then `docker compose up -d --build`); no registry image of the app is published. Nothing in your `.env` needs to change.
